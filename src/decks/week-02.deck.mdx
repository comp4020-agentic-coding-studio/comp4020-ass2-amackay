## Tokens

A database is tokens separated by white space, drawn from the 94 printable
ASCII characters. Three kinds:

- **keywords**, which all begin with `$`
- **labels**, which name statements
- **math symbols**, anything else

[Metamath book, section 4.1](https://us.metamath.org/downloads/metamath.pdf)

```notes
Everything you will ever parse is one of these three. A verifier's first job
is splitting the file on white space, and that is all the lexing there is.
```

---

## The keywords

```
${ $}  $c $v  $f $e $d  $a $p  $. $=  $( $) $[ $]
```

The last four handle comments and file inclusion.

[Metamath book, section 4.1](https://us.metamath.org/downloads/metamath.pdf)

```notes
Fifteen keywords. Learn them as pairs and groups the way they are spaced here:
block, declarations, hypotheses, assertions, terminators, and the four for
comments and includes.
```

---

## Statements: declaring

- `$c` declares constants
- `$v` declares variables
- `$f` and `$e` are hypotheses
- `$d` restricts substitution

[Metamath book, section 4.1](https://us.metamath.org/downloads/metamath.pdf)

```notes
After comments, a database is a sequence of statements. These four set things
up: what the symbols are, what a variable's type is, what a theorem assumes,
and which variables may not be substituted for the same thing.
```

---

## Statements: asserting

- `$a` asserts an axiom
- `$p` asserts a theorem, and carries its proof after `$=`
- `${ $}` bounds a block, which limits how long a declaration stays active

[Metamath book, section 4.1](https://us.metamath.org/downloads/metamath.pdf)

```notes
An axiom and a theorem are the same kind of statement, except that a theorem
has to earn its place with a proof. The block is scoping: what is declared
inside it is gone at the closing brace.
```

# A proof is a list of labels and nothing more.

Section 4.1.4 says what makes one correct. That is week 3.

```notes
This is the fact to take away. There is no proof language, no tactics, no
inference rules to learn: a proof names statements, in order, and the verifier
does the rest.
```

## Grammar one: MM.g4

The Antlr4 grammar behind the gramm verifier, on one screen:

- a database is `stat* EOF`
- a label is `[A-Za-z0-9._-]+`
- a math word is any run of characters without white space or `$`

[MM.g4](https://github.com/naipmoro/gramm/blob/master/src/main/antlr4/naipmoro/gramm/MM.g4)

```notes
Read it after the four pages and see how little is left once the prose is
gone. The three rules on this slide are the tokens slide, as a machine reads
it.
```

## Grammar two, and what a grammar is not

A [tree-sitter grammar](https://github.com/perrotuerto/tree-sitter-metamath/blob/main/README.md)
parses a database into a syntax tree from Python.

Neither says whether a proof is right. A grammar only tokenises and parses.

```notes
Two machine-readable grammars, and neither is a verifier. Keep the two jobs
apart in your head now, because in week 5 you write both halves, and the
parsing half comes first.
```

## `$j`

"a way to include information in metamath proof files which are not needed for
verifying, but which are useful for other tools"

A kind of comment (book, section 4.4.3), so a verifier may skip them.

[Metamath $j commands](https://github.com/metamath/set.mm/blob/develop/mm-j-commands.html)

```notes
The one part of the file the specification lets a verifier ignore. Week 7's
definition exercise depends on them, so know they exist and where they are
documented.
```
